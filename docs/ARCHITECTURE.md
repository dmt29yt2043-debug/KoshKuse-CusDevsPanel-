# Архитектура: голоса тестеров → дашборд

Исходное ТЗ: [`docs/TZ.md`](TZ.md). Здесь — решения, принятые на этапе 0, и почему.
Менять решение можно, но осознанно: сначала поправить этот файл, потом код.

## Схема

```
 Команда (браузер)                      VPS (cusdev.srv1362562.hstgr.cloud)                 Мак Макса
 ─────────────────                      ───────────────────────────────────                 ─────────
 страница загрузки ──файлы/текст──►  web (FastAPI)                                   агент (launchd, раз в 2 мин)
                                     │  хэш → дубль? → ffmpeg → .m4a                  │
                                     │  SQLite: conversations, очередь   ◄──next──────┤
                                     │                                   ──audio────► ~/CusDev-Pipeline/inbox/
                                     │                                                │   MacWhisper → .txt
                                     │                                                │   claude -p (подписка):
                                     │                                                │   разбор → проверка цитат
                                     │                                   ◄──result────┤
                                     ▼
                                   база ──► Google Drive: документ разговора + строка в _index (зеркало)
                                     ▼
                                   дашборд (тот же web): лента цитат, панель, срезы по СКЮ — читает базу
```

## Решения

**Р1. Очередь — в базе на VPS, а не в папке Google Drive.**
ТЗ предлагало очередь-папку в Drive, чтобы обойтись без бэкенда. Не выходит: статичная страница
не может писать в Drive, не показав ключ всем, у кого есть ссылка. Сервер нужен в любом случае, а раз
он есть, очередь в его базе проще и надёжнее: статусы, аренда задачи агентом, отлов дублей по хэшу,
«компьютер на связи» — всё это одна таблица, а не соглашения об именах файлов в папке.

**Р2. Разбор транскрипта — на Маке, по подписке Claude. Сервер Claude не вызывает.**
(Пересмотрено 08.10.2026, этап 1: было «разбор на сервере по API-ключу».) Макс решил платить
подпиской, а не API. Подписка живёт в CLI Claude Code на Маке, поэтому разбор переехал к агенту:
аудио → MacWhisper → `claude -p` со строгой JSON-схемой → `sanitize()` → результат на сервер.
Текст и скриншоты тоже идут через агента, минуя MacWhisper, — и тоже ждут, пока Мак включится.
Это осознанная плата за отказ от API: переписки редкие, а очередь и так умеет ждать.
Агент живёт в этом же репозитории и использует `cusdev.parse` / `cusdev.schemas`, запускается
из `.venv` репо. Секреты на Маке: токен агента и `CLAUDE_CODE_OAUTH_TOKEN` (`claude setup-token`,
живёт год). На сервере — только Google.
Расход: разбор идёт из лимитов той же подписки, что и интерактивная работа Макса. Разговор на
10–15 минут — один вызов; при десятках разговоров в неделю это незаметно.

**Р3. Хостинг — общий VPS, отдельный compose-проект.**
Поддомен `cusdev.srv1362562.hstgr.cloud`, наружу отдаёт host-Caddy, приложение слушает
`127.0.0.1:8210`. Как устроен прокси на этом VPS и где грабли с nginx — в памяти проекта Trello Mngmt.

**Р4. В Drive пишем от имени человека (OAuth, scope `drive.file`), а не сервисным аккаунтом.**
У сервисного аккаунта на личном Gmail нулевая квота: создать файл в чужой папке он не может, только
править уже существующие. Scope `drive.file` (только файлы, созданные приложением) не считается
чувствительным, поэтому OAuth-приложение можно перевести в Production без верификации Google —
и токен не протухает раз в 7 дней, как у бронирования встреч. **Проверить на этапе 4 первым делом.**
Запасной путь, если не выйдет: документ разговора — страница на нашем сайте, а в Drive только
индекс-таблица (её владелец — человек, сервисный аккаунт в редакторах — это работает).

**Р5. Источник правды — база. Drive — зеркало для людей.**
Дашборд читает базу и никогда не парсит документы (это требование ТЗ). Индекс-таблица в Drive
дублирует базу для тех, кто хочет открыть Sheets. Если запись в Drive упала, разговор всё равно
`done` и виден в дашборде; зеркало догоняется повтором.

**Р6. Строка индекса — это отзыв о СКЮ, а не разговор.**
В одном разговоре человек сравнивает индейку с уткой, и вердикты разные. Одна строка на разговор
с одним СКЮ и одним вердиктом ломает экран «срезы по СКЮ». Поэтому разбор возвращает список
отзывов (`items`), у каждого свои СКЮ, вердикт, темы и цитаты. Разговор без привязки к СКЮ
(например, только про доставку) — отзыв с `sku = null`.

**Р7. Формат (банка / сухой) — отдельное поле отзыва.** Не СКЮ (ТЗ, вопрос 3) и не тема: иначе он
съедает один из трёх слотов тем.

**Р8. Все аудио нормализуются на сервере в .m4a (ffmpeg).** MacWhisper получает один формат,
и .ogg/.opus из Telegram не надо проверять на стороне Мака. Длительность снимаем тем же ffprobe.

**Р9. Своя watch-папка: `~/CusDev-Pipeline/inbox/`.** Не `~/Zoom-Pipeline/inbox/` — там свой
процесс, который заберёт наши файлы. Папку один раз добавляют в MacWhisper → Watched Folders руками.

**Р10. Имя файла: `YYYY-MM-DD HH.MM Имя тестера [abc123].m4a`.** Шесть символов id в скобках —
чтобы агент однозначно сопоставлял .txt с задачей даже при двух разговорах в одну минуту.

**Р11. Цитаты проверяет код, а не модель.** Цитата принимается, только если дословно входит
в транскрипт (после нормализации пробелов, регистра, «ё→е» и кавычек). Не вошла — выбрасывается
и пишется в лог разбора. Это бесплатно и надёжнее любой просьбы в промпте.

**Р12. Доступ — секретная ссылка.** `/?key=…` ставит cookie на 90 дней. Агент ходит с отдельным
токеном в заголовке `Authorization: Bearer …`. Ролей и логинов нет (границы прототипа).

**Р13. Стек.** Python 3.12, uv, FastAPI, Jinja2 + ванильный JS без сборки, SQLAlchemy 2 + SQLite
(WAL), Anthropic SDK. `web` и `worker` — два процесса одного Docker-образа. Postgres не нужен:
десятки разговоров в неделю, один писатель.

**Р14. Модели.** Разбор одного разговора — `PARSE_MODEL` (по умолчанию `claude-sonnet-5-5`;
на этапе 1 сравниваем с `claude-haiku-4-5`). «Разобрать всю подборку» — `BATCH_MODEL`
(`claude-opus-5-5`), только по кнопке. Вызов — `claude -p --json-schema … --tools ""` из
временной папки, без MCP, настроек и истории сессий: чистый вызов модели, а не агент.

## Жизненный цикл разговора

```
аудио:  queued ──agent/next──► transcribing ──transcript──► parsing ──result──► done
текст:  queued ──agent/next──────────────────────────────► parsing ──result──► done
скрин:  queued ──agent/next──────────────────────────────► parsing ──result──► done
                 любой шаг ──ошибка──► failed (повтор — кнопкой)
```

Все шаги после загрузки выполняет агент на Маке (Р2); сервер только выдаёт задачи и принимает результат.

- `transcribing` / `parsing` — аренда. Если за `JOB_LEASE_MINUTES` (120) текст не пришёл, задача сама
  возвращается в `queued`: Мак выключили посреди работы — ничего не потерялось.
- `queued` дольше `QUEUE_WARN_HOURS` (24) — подсвечивается на странице.
- «Компьютер на связи» — агент отзывался за последние `AGENT_STALE_MINUTES` (10).
- Запись в Drive — отдельный флаг `drive_synced`, не статус: на `done` не влияет.

## Контракт агент ↔ сервер

Все запросы с `Authorization: Bearer $AGENT_TOKEN`. Любой запрос обновляет «последний раз на связи».

| Метод | Путь | Ответ |
|---|---|---|
| `POST` | `/api/agent/heartbeat` | `204` |
| `POST` | `/api/agent/next` | `204` — очереди нет; `200 {"id", "kind", "filename", "channel", "sku_hint"}` — задача взята в аренду |
| `GET` | `/api/agent/jobs/{id}/source` | аудио `.m4a`, картинка или текст — исходник задачи |
| `POST` | `/api/agent/jobs/{id}/transcript` | тело — текст UTF-8; `204`; статус → `parsing` (только для аудио) |
| `POST` | `/api/agent/jobs/{id}/result` | `{"transcript", "result": ParseResult, "warnings", "model"}`; `204`; статус → `done` |
| `POST` | `/api/agent/jobs/{id}/fail` | `{"reason": "…"}`; `204` |

Агент держит одну задачу за раз (порядок — по времени загрузки) и хранит у себя
`~/CusDev-Pipeline/state.json` (какая задача в работе), чтобы пережить перезапуск.
После отдачи транскрипта аудио и .txt переезжают в `~/CusDev-Pipeline/_processed/YYYY-MM/`.

## Данные

```
testers         id, name (уник.), note, created_at
conversations   id, content_hash (уник.), tester_id, source_kind (audio|text|image), channel,
                talked_at, note, sku_hint, original_filename, duration_sec, size_bytes,
                status, error, claimed_at, transcript, summary, speakers (one|several|unknown),
                parse_model, drive_doc_url, drive_synced, created_at, updated_at
feedback_items  id, conversation_id, sku, format, verdict, themes (JSON-список ≤3)
quotes          id, feedback_item_id, text, theme
settings        key, value   ← agent_last_seen и прочее одиночное
```

Контракт результата разбора — `cusdev/schemas.py` (`ParseResult`). Закрытые списки — `config/taxonomy.yaml`:
в базе хранятся ключи (`turkey`), на экране — подписи («индейка»). Переименовать подпись можно
в любой момент, ключ — никогда.

## Google Drive (этап 4)

```
Kosh Kuse — голоса тестеров/
  _index                         ← Google Sheet, строка на отзыв (Р6)
  2026-10/
    2026-10-08 Анна К. — индейка  ← Google Doc: шапка, саммари, отзывы, цитаты, полный транскрипт
  _audio/2026-10/                ← оригиналы
```

Колонки `_index`: id (`хэш12-№`), дата, тестер, скю, формат, вердикт, темы, цитаты, канал, ссылка.

## Чего нет и не будет в прототипе

Анкеты и рассылки, Telegram-бот, автоматические тренды, роли и логины, облачное распознавание
как резерв. Подробности и причины — в ТЗ, раздел «Границы прототипа».
